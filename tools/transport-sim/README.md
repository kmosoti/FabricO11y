# Packet-slot transport simulator

This standalone Rust package runs the registered H1 M0 sender-window and M1 receiver-credit comparison, plus the registered M2 unscheduled-prefix comparison. It is a deterministic scheduling model, not Fabric O11y network transport. A completed message gets an immediate **modeled commit** at the receiver; no EventLog or disk operation occurs.

```sh
cargo test --manifest-path tools/transport-sim/Cargo.toml --offline --locked
cargo run --release --manifest-path tools/transport-sim/Cargo.toml --offline --locked --bin transport-sim -- h1 <fresh-output-dir>
cargo run --release --manifest-path tools/transport-sim/Cargo.toml --offline --locked --bin prefix_probe -- m2 <fresh-output-dir>
```

Each output directory must not exist. Each command writes `summary.csv`, `messages.csv`, and `bursts.csv`. H1 groups rows by seed `0..9` and variant `M0`, `M1`. The M2 command groups rows by profile (`small`, `incast`), seed `0..9`, and variant `M1`, `M2`, with a leading `profile` column. Message rows are ordered by producer then sequence within each group. Byte metrics identify payload or wire bytes by column name: sender queue and completed bytes are payload; switch queue and `data_wire_bytes_sent` are wire bytes. `control_bytes` counts separate 32-byte announcements, grants, packet receipt ACKs, or modeled durable ACKs, without control-link contention. M2's embedded 32-byte announcement is reported separately in `embedded_metadata_bytes`.

At each tick, the model releases a burst, handles due control and data events, issues M1 or M2 scheduled grants, samples queue occupancy, lets each sender send at most one packet, and transmits at most one FIFO switch packet. Data reaches the switch four ticks after send; an egress transmission during tick `t` reaches the receiver at `t+1`. Control reaches a producer or receiver four ticks after issue. Thus a grant issued at tick `t` permits a send at `t+4`; with an idle switch, delivery occurs at `t+9`. A completed message commits in the same receiver tick, and its durable ACK reaches the producer four ticks later.

M1 sends a separate announcement at release and requires a receiver credit for every DATA packet. M2 sends one uncredited DATA packet as soon as the sender can send. Its first wire slot carries at most 1,468 payload bytes and a 32-byte announcement; the receiver learns the message only when that packet is delivered. Remaining DATA packets carry at most 1,500 payload bytes and each requires a credit. The first packet is outside the nine-packet global scheduled-credit budget. The `unscheduled_prefix_packets` summary column is the effective value, zero for M1 and one for M2. The `small` profile has eight producers sending 148-byte messages; `incast` has 32 producers sending 65,536-byte messages. Both use the registered seed-paired traces and fixed settings in [the M2 record](../../docs/experiments/ablation/unscheduled-prefix-m2-run-01.md).

Sender queue bytes are **unsent** payload, sampled before sender wire-send. Retained full message copies are separately sampled and held until durable ACK. The per-producer cap is 131,072 payload bytes in H1 and M2 `incast`, or 592 payload bytes in M2 `small`. Switch bytes are sampled after packet arrivals and before egress. Each burst's hot-spot peak spans its release through the tick when all its messages complete, including any overlapping bursts; the receiver admission queue is zero by construction. Injection intervals are half-open and drain deadlines inclusive: `[0, 1_760_000)` and tick `1_770_000` for H1 and `incast`, or `[0, 10_000)` and tick `11_000` for `small`.

The run fails on queue-cap overflow, receiver-credit overgrant, packet-accounting error, ownership error, or incomplete delivery/ACK at the deadline. There is no packet loss, retransmission, rejection policy, switch priority, CPU model, or real durability in this first cell.
