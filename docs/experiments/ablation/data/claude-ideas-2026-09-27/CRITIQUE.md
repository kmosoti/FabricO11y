# Independent critique of I1–I6

Scope: six `idea` entries in `IDEAS.jsonl`, read 2026-09-27. I did not change the study or repository. The executable conceptual probes are `/tmp/fabric-mad-scientist-probes.py`; `python3 -B /tmp/fabric-mad-scientist-probes.py` exited **0** and printed six concrete counterexamples. These probes test the claims' logic, not a physical crash model or performance.

Current baseline: the application has one FOL2 single-writer log, two syncs per event, and no production query service or sender ACK protocol. S1 is a separate in-memory research probe over replayed rows, with optional summaries that fall back to scans. Thus A3's independently published production index and A4's two implemented ACK ledgers are proposed premises, not existing implementation. See `docs/CURRENT.md`, `src/log.rs`, and `docs/experiments/ablation/storage-query-s1-run-01.md`.

## Findings by idea

| Idea | Claimed category / status quo | Counterexample and status | My repair, absent from the original |
| --- | --- | --- | --- |
| **I1 coverage receipts** | **Known mechanism, new system composition to test.** Breaks A1/A5: completeness comes from an authenticated writer block set rather than the reader's implicit list. Hash-chain query verification has close prior art in [vChain](https://arxiv.org/abs/1812.02386); the Fabric durability/query combination still needs its own evaluation. | Probe `I1_sealed_false_negative`: one sealed block contains `rare`, but a freshly sealed summary says `{common}`. Its chain hash verifies while the query returns empty. This violates exact predicate completeness without any stale summary or hash collision. A chain head also cannot by itself let a verifier check an omitted block's summary digest; it needs authenticated per-block commitments or paths and a separately trusted head. The listed kill test only injects deletion, stale summary, and order. **Repair before correctness claim.** | Define the proof object and trust root; at seal time validate summary exclusion against exact row tokens, and bind row digest, summary digest, block ordinal, total count, and query snapshot. Verify the exclusion rule as well as the receipt. An independent audit or trusted builder is needed if the writer can seal an incorrect summary. |
| **I2 one-sync group seal** | **Known journal family, interesting contract ablation.** Breaks A2's first ordering sync. SQLite's [WAL format](https://www.sqlite.org/walformat.html) already has checksummed frames and commit frames; the proposed single-sync FOL2 comparison is still worth measuring. | Probe `I2_corrupt_acked_group`: a full group was ACKed, then one data byte changed. Its full seal is present and its hash mismatches. The proposal says otherwise truncate the whole group, which silently discards an ACKed event. The violated property is **fail closed on detected corruption of a previously committed group**, under the same successful-sync/healthy-media assumptions as FOL2. Their sector-subset test covers interrupted writes, not post-ACK corruption or a failed sync's ambiguous state. **Repair before correctness claim.** | On a full seal with a hash mismatch, return corruption and preserve bytes; truncate only an incomplete, plausibly interrupted tail under stated crash assumptions. Poison on any write/sync error, require independent recovery after ambiguous failure, and state sector atomicity, write ordering, directory durability and hash assumptions. Separate group-size-1 throughput from batching gains. |
| **I3 residual answers** | **Viable research idea with known incomplete-answer semantics.** Breaks A5: availability becomes explicit residual work. [Levy 1996](https://www.sigmod.org/publications/dblp/db/conf/vldb/Levy96.html) already treats query completeness over incomplete data; physical block-position composition is a distinct concrete design. | Probe `I3_cross_snapshot_residual`: snapshot S has positions `0:A,1:B`; partial answer gives `0:A`. A later compacted snapshot T has `0:B,1:C`; residual gives `1:C`. Merge yields `A,C`, equal to neither snapshot. Violates exactness for one snapshot. Duplicate EventIds are harmless **only if** unique physical position is stable inside that snapshot; retrying a residual must not emit that position twice. **Keep, conditioned on repair.** | Bind immutable snapshot head, block IDs/content digests, predicate bytes and order semantics into the residual. Merge by `(snapshot, block, row ordinal)` with idempotence, reject mismatched snapshots, and report permanently corrupt/unavailable blocks as unresolved rather than claiming eventual closure. |
| **I4 IBLT ACK reconciliation** | **Known probabilistic set-reconciliation mechanism, proposed use for delivery audit.** Breaks A4's sequence comparison. [Goodrich–Mitzenmacher IBLT](https://arxiv.org/abs/1101.2245) promises listing with high probability below capacity, not unconditional exactness. | Probe `I4_two_stale_ledgers`: sender ACK ledger and owner seal ledger both contain tuple `(7,42,h)`, but actual replayed disk is empty. Difference is zero and audit falsely passes. Violates the intended durable-owner check: two agreeing stale ledgers are not independent evidence of retained bytes. An IBLT set also loses multiplicity for identical retry tuples unless explicitly modeled. Key/checksum collisions and decode capacity prevent an unconditional false-empty rate of zero. **Reject current detector claim.** | Rebuild the owner's inventory from independently verified disk blocks or authenticate a durable snapshot against an external witness. Bind both views to an epoch and stable producer sequence; represent multiplicity or enforce receiver deduplication. Report probabilistic error bounds and fallback on every undecodable state. Sender ACK history needs independent persistence after it forgets payloads. |
| **I5 embedded commit summary** | **Plausible atomic publication idea, but sync-shadow performance claim is unsupported.** Breaks A3, which is not an implemented production phase. | Probe `I5_single_thread_sync_shadow` follows current FOL2 sequencing: `write frames → sync blocks caller → sync returns → build summary → write commit → sync commit`. The summary cannot be both computed from completed writes and placed into a commit marker during that same blocking sync by the current single thread. A fresh embedded summary can still be semantically wrong; co-location removes staleness, not false negatives. **Keep as a design, revise cost claim.** | Precompute from an immutable block before sync, or use an explicit second worker and measure its CPU/critical path. Make summary bytes part of the commit checksum and validate summary/exclusion against rows before sealing. Compare with the same block batching and sync schedule, not per-event FOL2 versus block commits. |
| **I6 lossless template decomposition** | **Potential exact encoding plus index, but the proposed absence certificate is false.** Breaks A6's verbatim-byte representation. | Probe `I6_cross_boundary_token`: template `time{v}`, `v=out`, reconstructed body `timeout`. The actual S1 predicate `body.split_whitespace().any(word == token)` matches `timeout`; neither the template piece `time` nor variable `out` contains the token. Dictionary exclusion loses a row despite perfect bit-identical round trip. Violates no-false-negative pruning. **Repair before correctness claim.** | Index tokens from the fully reconstructed row under the exact S1 tokenizer, or store boundary context sufficient to reconstruct crossing tokens. Keep byte-level round-trip check for storage fidelity, but test token-index soundness separately. Preserve raw float bits, whitespace, Unicode and fallback-to-verbatim cases. |

## Top three to falsify next

1. **I2, revised one-sync seal.** It attacks the measured append boundary. Enumerate crash sector subsets *and* complete post-ACK corruption, failed-sync ambiguity, and reopen rules; fail closed on the latter. Only after this passes compare group-size-1 sync counts and durable events/s on the Stage 6 host.
2. **I1, authenticated coverage.** It targets a real missing premise in S1. Inject a freshly sealed false-negative summary, an omitted block, an untrusted/replaced head, and a mismatched snapshot. Require a verifier to prove every block disposition without row rereads for the receipt, while the seal builder's exact summary invariant is checked separately.
3. **I3, snapshot-bound residuals.** Its contract can be checked cheaply. Randomize availability and repeated retries over immutable snapshots with duplicate EventIds, then inject compaction/position reuse and require explicit rejection of cross-snapshot composition.

Novelty conclusion is deliberately narrow: these cited sources establish close mechanisms, not that any Fabric-specific combination is already published or unpublishable. No idea is rejected for being unconventional or expensive. The rejections above arise from concrete counterexamples to stated exactness or durable-ownership claims.
