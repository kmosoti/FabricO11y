# Review of revised I7/I8/I9

Read the I7/I8/I9 `idea` entries in `IDEAS.jsonl` on 2026-09-27. `IDEAS.md` still describes the original I1/I2/I3, so this review uses the ledger entries. I did not edit the study or repository. `python3 -B /tmp/fabric-mad-scientist-revision-probes.py` exited **0** and printed four conceptual counterexamples. The probes are small logic models, not a filesystem crash simulation.

**I7 — conditionally coherent, but split its guarantee.** The trusted builder's exact row check can reject a false-negative summary before sealing, and a receipt verifier with an independently trusted root can check ordinal coverage, digest binding, and whether a *given* summary excludes the query. Those are different actors. Input `row=rare, summary=common` demonstrates the distinction: if a buggy builder seals this pair, the receipt and Merkle path remain valid; `builder_version` identifies the builder but cannot prove its semantics. The independent full-scan oracle catches the bug in tests, not the row-free receipt verifier at runtime. Replace the thought experiment's prediction that “every injected defect is rejected by path, count, digest or exclusion re-check” with two predictions: trusted builder rejects invalid summaries; verifier rejects malformed or inconsistent receipts under the builder-correctness assumption. A sealed semantic-bug injection should be *accepted by the receipt verifier* and detected by the separate builder oracle; otherwise the preregistered non-vacuity check expects an impossible property. A scanned disposition also does not attest returned row completeness, which the entry correctly calls out as a non-malicious executor assumption. Check summary inclusion against the exact tokenizer, tenant and time predicate implemented in S1 before commit.

**I8 — correctness direction improved, but two assertions still conflict.** Input persisted-sector subset `{seal sector}` with `{frame sector}` absent yields a complete seal whose group hash mismatches. Under the revised rule it must return **corruption and preserve bytes**. The thought experiment instead predicts truncation for *any* subset of the in-flight group; the four-subset probe gives `neither=truncate`, `frame-only=truncate`, `seal-only=error_preserve`, `both=accept`. Narrow the prediction to “every subset either produces a committed full group, a truncatable plausible incomplete tail, or a fail-closed error; none exposes a partial group or discards an ACKed group.”

The failed-sync reopen claim needs a separate correction. Histories `sync returns Ok` and `sync returns EIO` can leave identical valid frame-and-seal bytes. The file alone therefore cannot make a later `open` refuse auto-resume “exactly as FOL2 does”; FOL2's handle is poisoned **in process**, and its docs require the operator to retain error knowledge and rebuild from an independent trusted source. State that an external supervisor/error ledger or caller contract blocks reopen after EIO. Without that external witness, the read-only file scanner cannot distinguish the histories. Add a test that supplies this external error state to the recovery policy; do not claim the format persists it. The full-seal mismatch fail-closed rule is a sound repair to the original silent truncation, conditional on successful sync being honored and no later media failure.

**I9 — main counterexample repaired; tighten merge conflict semantics.** Snapshot head and block digest binding reject the earlier `S: A,B` / `T: B,C` cross-snapshot merge, and physical coordinates preserve duplicate EventIds. Input two retry results at identical coordinate `(headS,3,2)` but values `A` and `B` shows that “set union keyed by coordinates” alone is underspecified. Require equality of event bytes or authenticated row digest at duplicate coordinates; reject conflicting values instead of silently choosing one. Also specify that `R_c` is an exact predicate result for covered blocks (through a trusted evaluator/valid summary), and that an unresolved corrupt block cannot become an empty residual. The E3 test should inject same-coordinate conflicting rows in addition to repeated identical retries. No broad obstacle remains under an immutable, independently identified snapshot and a trusted exact evaluator.

These are conceptual repairs to claims and proposed tests, not approval of an implementation or performance result. I7 and I9 are ready for focused preregistration after the wording changes. I8 needs its recovery outcomes and failed-sync authority corrected first.
