# Real Spindle medium/enterprise volume: local protocol

Registered before implementation/execution on consolidated `milestone/streaming-segment-output`, base `13696e4`. Follow-up to [synthetic fleet results](scaled-fleet-local-run-01.md) and [native dev/small](dev-small-local-run-01.md). This explicitly uses **20 actual fabric-node processes**, native file collection, durable Spool, native TLS sender, real server commit/reclaim/Segments. No direct Batch injection or substitute in-memory forwarder. It tests aggregate volume, not 200/2,000 physical hosts.

## Fixed sequence and workload

Medium then enterprise, fresh independent state, fully stop/recover/analyze the first before the second. Twenty nodes evenly share aggregate ordinary rates 10,000 / 100,000 log events/s, respectively. Native host metrics every 15 seconds, no spans/concurrent queries. Source bodies are 900-byte ASCII, uniquely tagged, half repeated/half deterministic xorshift printable entropy, seed 2703163393. A dependency-free native producer writes selected app log files on monotonic 100 ms ticks, records scheduled and post-write wall times plus lateness per node/tick. Native generation avoids Python becoming the intended 100k/s feeder; actual producer timing is still measured.

Each workload: settle five seconds, 10 seconds ordinary, five seconds 3× burst, ten seconds ordinary recovery. Expected source logs 350,000 / 3,500,000. Producer catches up overdue ticks without dropping offers. After offers end, give native collection/delivery up to 120 seconds to drain file backlog and ACK the latest observed Batch, then 20 seconds quiet for server sealing, graceful shutdown, fresh-process durable replay and independent source comparison. Report incomplete drain rather than silently extending the deadline or throwing away source logs.

Server uses one sealing worker, 64 MiB journal files, 1 GiB journal ceiling, 8 GiB/24-hour Segment retention. Each native Spool is byte bounded at 256 MiB. Server affinity two CPUs, Spindles/producer two other CPUs, shared four-CPU-equivalent/16-GiB environment. Address-space bounds server 4 GiB, individual node 512 MiB; actual process RSS, cgroup charges and file caches are separate. Memory budget remains a deployment dimension; no installed profile or production semantics change.

## Dimensions and hypotheses

Observe data fidelity, dual-clock latency, full source-to-ingestion/ACK and scheduled-to-ingestion latency, throughput, source-generation delay, native collection backlog, durable Spool occupancy, journal backlog, recovery, server/node/producer CPU and RSS, logical storage and /proc I/O, and shared cgroup memory/cache pressure. Avoid collapsing these into one score. Actual encoded bytes/event and retained Segment volume are measured. Native forwarding retries and durable ACK hashes are retained.

Record-weighted nearest-rank p50/p99: collection clock is OTLP observed_ns; ingestion clock is persisted server receive time before sync; ACK clock is node stdout observation (upper observation delay, not exact native ACK clock). Source timestamp is post-write visibility, scheduled timestamp monotonic schedule projected to realtime. Include any clock inversions rather than clamping; source post-write may race collection during a write. Same-host realtime-minus-monotonic offset range >5 ms flags clock uncertainty; no cross-host sync claim. Records share Batch clocks.

H1 per tier: producer per-tick completion-lag p99 <=100 ms; all planned unique exact source bodies durably recovered without gaps/duplicate logs, every observed ACK matched recovered exact Batch SHA-256, contiguous recovered sequences, clean exits, drain within 120 seconds, collection-to-ingestion and ACK-observation p99 <=1 second, source-to-ingestion p99 <=2 seconds, server RSS <=2 GiB, every node RSS <=64 MiB, offset range <=5 ms. H0: at least one condition fails. An incomplete population never passes latency just because missing records are excluded. Preserve all failures and separately state producer-limited, collection-limited, forwarding/backpressure and server-capacity interpretations only to the degree evidence supports them.

## Verification, resource/evidence bounds

Compare fresh recovered log hashes against every original app-file line with an independent Python OTLP decoder and a disk-backed SQLite audit. Verify full offered count, unique tag set, exact body bytes, recovered sequence and ACK hash custody. This is not the full independent delivery-oracle transcript; no query answers are tested. Before trials, accept identical and reject changed/missing log controls. Never substitute a reconstructed source from server replay. Record source-file SHA-256 to retain the deterministic producer recipe, source write clocks, compact counted data-clock groups, exact recovered Batch hashes, stdout events and once-per-second resources/clock/I/O samples.

Per trial wall <=1,200 seconds including analysis; children/producer each have bounded waits. Timed-phase logical disk cap 12 GiB; analysis cap 16 GiB; workspace free floor 4 GiB. Monitor once/second (possible bounded sampling overshoot), stream temporary replay, bound SQLite cache, retain failure evidence before any retry. Native producer source files/SQLite are scratch-owned; do not delete unrelated data. Stop only owned children. Compressed retained evidence <=128 MiB/tier, exclude credentials/keys. No Docker, privileged cgroup installation, destructive faults, releases, sharding or qualification. Protocol is committed separately from runner/producer.
