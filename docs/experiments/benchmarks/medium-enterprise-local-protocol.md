## Scope and fixed workloads

Two sequential native simulations against the real TLS/durable server: medium then enterprise, separate fresh state. Extend the existing `spindle_sim` example with optional log factor/body size while retaining its original defaults and frozen-generator test. No production protocol, memory profile, durability or oracle changes. Simulated identities keep pending data in memory; this tests server/fleet event-rate behavior, not deployed Spindle collection/Spool cost or physical fleet networks.

- Medium: 200 identities, 50 logs/identity/second = 10,000 logs/s; enterprise: 2,000 identities, 50 logs/identity/second = 100,000 logs/s. Bodies 900 bytes, half repetitive/half seeded entropy, seed `0xA11FA001`, native simulator metrics every 15 seconds. Encoded volume is measured, not assumed 1 KiB/event.
- Planned phases: seconds [0,10) ordinary, [10,15) 3× burst (150 logs/identity/second), [15,25) ordinary recovery. Expected 350,000 / 3,500,000 logs if all planned offers are generated. Stop offering after 25 logical seconds; existing simulator watchdog allows up to 60 additional seconds to drain pending Batches. Allow server another 30 seconds to seal, then gracefully stop and freshly replay custody.
- Simulator: 128 native worker threads multiplexing identities, one Batch in flight per identity, original per-identity config polling. Collection timestamp is the simulator's data-generation clock, not an application's physical collection time. Record scheduled-versus-actual creation lag per identity/sequence to expose generator contention/coordinated omission; delayed scheduled cohorts stay attributed to their planned phase.
- Server: two affinity CPUs, one sealing worker, 64 MiB journal files, 1 GiB journal ceiling, 8 GiB/24-hour Segment retention (no intended eviction). Generator on two other affinity CPUs. Same shared four-CPU-equivalent/16-GiB environment as native pilots. No Docker/systemd installation or hard 4-GiB deployment emulation. Server address-space cap 4 GiB, simulator 6 GiB; process RSS is measured separately. Budget is a deployment dimension, not an architectural constant.

## Measurements, hypotheses and decision

Per-record collection-to-ingestion latency uses independently decoded OTLP observed time and persisted server receive time; p50/p99 nearest rank, record-weighted, overall and by planned phase. Collection-to-ACK uses simulator's own response end clock. Also report planned scheduled-offer-to-ingestion/ACK so a generator that runs late cannot pass on low created-to-ingested latency alone. Report request RTT, actual generation duration/rate/lateness, ACK rate and completion, retries/back-pressure, sealed backlog, server/simulator RSS and CPU, once-per-second realtime-minus-monotonic clock range, logical I/O/state volume, and effective placement/limits. Same-host wall clocks are checked for steps >5 ms, not distributed synchronization. Samples share Batch clocks.

H1 for each tier: all planned cohorts generated with per-identity creation-lag p99 <=1 s, all planned logs durably recovered, simulator pending count zero, independent digest-projected delivery oracle passes, clean children, collection-to-ingestion and collection-to-ACK p99 <=1 s, scheduled-to-ingestion p99 <=2 s, server peak RSS <=2 GiB, simulator peak RSS <=4 GiB, clock-offset range <=5 ms. H0: one or more criteria fails. Preserve failing and generator-limited outcomes; a 100k events/s intention is not measured attainment. No capacity, enterprise qualification, sustained production retention or multi-server claim follows from 25 seconds.

## Correctness, bounds and evidence

Fresh replay extracts exact Batch bytes; project SHA-256 to the existing independent delivery-oracle transcript as in the fleet harness, and independently decode every log count/body size and its observed clock. Verify the full expected count; zero pending and ACK custody; never trim failed attempts or late cohorts. Before workload runs, test default simulator entropy against its frozen Python fixture and reject an intentionally dropped recovery in a miniature independent-oracle negative control. Record command/revision/binary hashes, actual environment, resource samples, source/attempt events, compact Batch clock records and complete oracle verdicts.

Per tier: 900-second wall cap including recovery/analysis; 12 GiB logical trial-disk ceiling and 4 GiB free-space floor sampled each second (sampling overshoot is possible); fresh owned scratch only; stop only owned children on violation. Stream large replay to disk and parse incrementally; retain compressed source/attempt/oracle and clock evidence with a 128 MiB/tier evidence budget. Keys/tokens stay scratch-only. Run medium completely before enterprise, and no broad builds/checks during timed phases. Preserve any stopped/failing run before deciding whether environment supports the second run. Finite resource/latency budgets are pilot criteria, not edits to product qualification gates.
