# Sequential native responsibility isolation, protocol 1

Registered before implementation/measurement, base `ddf30f8`. Owner authorizes isolated benchmarks and scratch cleanup before the later composite/deployment tests. This is exploratory attribution, not qualification, a default-selection decision or a composite run. No runtime semantics, durability, oracle or wire format changes.

## Fixed workloads and order

Use a benchmark-only Rust example invoking existing native public APIs; no new dependency/crate/port. Fixture seed 42, 4,096 uniquely tagged ASCII log bodies; alternate repeated and deterministic printable entropy. Body sizes 128, 900 and 3,500 bytes, 128 logs per encoded Batch, fixed identity/sequence/time. Three fresh-process trial pairs per applicable case, uninstrumented allocator versus counted allocator, alternating order by pair. Default release build is the timing baseline; counted release build measures live/cumulative allocation. Fixture generation and reporting stay outside operation spans. Input stays resident when explicitly needed; count starting live bytes separately from incremental peak. Files are newly generated buffered local files, not a cold-device claim.

Sequential groups: collection; delivery; storage; processing; query; control; scheduling; buffer analysis; observer calibration. Do not overlap benchmark processes or build/check work with measurements. Keep stage boundaries accurate even when a native operation crosses responsibilities. Within a group each case/pair runs sequentially; capture and verify compact evidence before deleting that trial's owned scratch. Cleanup only directories created by this runner, with an ownership marker.

- Collection: actual file reader, ten full cursor scans per shape; separately native host sampler. Check every body and gap/backlog/cursor behavior on the valid fixture. No Spool in isolated file-read timing.
- Delivery: precommitted native Spool, native Sender and real loopback TLS/durable server, one Batch in flight. Time Spool retrieval, send/answer and durable ACK separately, plus setup and replay outside timed work. This removes collection deliberately. No substituted in-memory forwarding. Server serves real grouped-sync semantics.
- Storage: native Spool append/read/ACK/reopen, then server intake submit-to-durable-answer and stopped native replay. Public native operations include their encode/clone/hash/sync costs; do not label them pure disk timings.
- Processing: native row extraction and explicit native-equivalent row sort; full Segment build/publication is a separately labeled inclusive boundary. Do not subtract unrelated trials to manufacture compression/sync attribution.
- Query: actual History scan and walk over identical native tail and/or built Segment fixtures; empty, selective, common and broad log searches, twelve requests/shape. Retain actual answers and grade with unchanged independent query oracle. Serialization timed separately. This is engine isolation, not HTTP/CLI or first-query visibility.
- Control: actual durable enrollment/configuration, poll and inventory at 1/20/200 nodes; ten updates, polls and inventory operations after enrollment. Check revisions, status and restart state. Fixture provisioning is separately measured rather than hidden.
- Scheduling: actual native server intake/rotation and sealer pass with 1 versus 2 workers, 900-byte shape; retain exact replay before/after and source/Segment/journal inventory. Pass time includes native reads/build/reclaim/retention; per-thread occupancy/barrier phase profiling remains unavailable unless explicitly captured.
- Buffer/observation: analyze counted live/peak/cumulative allocations and process/cgroup memory across preceding cuts; three matched pairs calibrate allocator overhead. Separately time fixture hash and JSON serialization observation. No claim of complete allocation ownership, native stdout overhead or observer-free physical IO.

## Metrics, controls and bounds

Record operation count/units, monotonic wall ns, CPU seconds and proc IO around boundaries where measurable, start/live/peak/cumulative allocation bytes, VmHWM, sampled cgroup memory categories/events, source/binary hashes, command/exit, exact counts and correctness. Timer and counter access overhead is part of the measurement method; retain calibration and tick-resolution limitations. p50/p99 are operation-weighted nearest rank, per trial, not record-weighted deployment clocks. Keep individual trials, failed/partial populations and instrumentation cost; do not pool unlike shapes or sum inclusive nested phases.

Correctness gates: exact source/body/Batch hashes, no silent drop/alteration/duplicate or unexpected gap, sequence/cursor/ACK ordering, independent query-oracle match including envelopes, control persistence/revisions, exact pre/post-seal replay. Before measurements inject a changed/missing body and altered query row/hash into copied evidence; controls must reject. Timing is reported, not gated. Each comparison is descriptive over three pairs, not statistical proof. No improvement/default claim without later independent confirmation.

Per child wall <=180 s and address space <=2 GiB; whole suite <=3,600 s; per-trial logical scratch <=1 GiB, workspace free floor 4 GiB, retained compressed evidence <=256 MiB total. Sample live processes/resources where duration allows, retain proc high-water for short cuts. Preserve failure/evidence before retry; preregister changed workloads or criteria. Stop only owned processes. Graceful server stop then fresh replay; exclude tokens/private keys from retained evidence. Successful cleanup records disk bytes removed and free space before/after. Do not delete historical runs or unrelated caches to meet bounds. No Docker/systemd/cgroup installation, physical faults, enterprise tier, consumer/composite benchmark or shipping configuration changes.
