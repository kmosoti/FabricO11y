# Registered R3 runtime integration controls

Prospective registration, 2026-10-15. This implements the existing
[R3 contract](soak-protocol-r3.md); it changes no gate, oracle or phase allowance.
Source controls and native execution require separate admitted launcher cells.
No execution or acceptance is claimed by this registration.

`soak_tier.py --r3 --admission PATH --admission-sha256 SHA` selects the new
runtime. The caller pins the actual admission bytes independently. An admission
record binds the exact clean harness source, canonical package receipts, separate
native helper/build authority, console source, complete freeze manifest, and
exclusive output/checkpoint paths. A self-consistent replacement admission is
not independent owner authority. Full mode additionally requires all six real
S1 maxima and their stopped source receipts; smoke retains full rate/identities
and records shorter exposure as smoke only. Neither can grade without concrete
native publication and browser clock/session evidence. Missing mechanisms are
explicit admission refusals, never asserted successful flags.

The outer interval starts at systemd's actual service activation monotonic
timestamp. Six ordered, disjoint phase records use the registered ceilings.
Before and after blocking boundaries the runtime checks the phase and outer
remaining allowance. A hard process alarm interrupts progressive I/O and
cleanup when a deadline expires. Each probe has its own stoppable cadence;
workers acknowledge readiness before native simulator launch and are joined
before their raw ledgers close. Every raw query page, management answer, failed
attempt and resource sample is retained. Refusals remain failures. The actual
simulator begin bracket anchors sample classification and the conservative end.
Early exit, missing worker offers, lost probes or an interval one ns short fails.

Shutdown confirms zero exits and empty simulator/server/browser groups before
same-filesystem, no-replace rename of complete stopped trees. Checkpoint never
copies raw data. Measurement and runtime receipts remain pending; the launcher
must subsequently stop empty. A separate default contained grader authenticates
the immutable pending receipts, complete raw manifests and independently pinned
outer receipt, then runs the existing dump/custody/oracle/gates. Exclusive
grading output cannot overwrite measurement/runtime evidence. Failed or partial
state is retained; failure grants no deletion permission.

Prospective source controls must reject: missing native/UI binder; changed
admission bytes; shortened or shifted exposure; probes becoming ready after
launch; dead worker, lost cadence or failed raw page; wall-time cohort arithmetic;
phase borrowing, interrupted blocking I/O, forced shutdown; nonempty process
groups; checkpoint copying; changed raw/pending inputs; absent/mismatched outer
stop; substituted package/helper/source pins; rewritten grading destination.
Existing ten-gate adverse controls and independent Python oracles stay unchanged.
Source controls cannot establish native lifetime, real UI continuity, S1 headroom
or full acceptance. Their exact commands, exits, pins and containment receipts
must be recorded separately by the admission scheduler.

## Native UI timer and refresh observation

The R3 adapter records the actual native `setInterval(5000)` registration and
each invocation, request start, HTTP status and body completion; it preserves
the native view's busy/error/visibility decisions. Timer callback timestamps
are observations, not ideal deadlines. Request-gap distributions and their
maximum remain descriptive. Reuse the existing twenty-second progress bound
(the configured five-second poll plus fifteen-second transport deadline).
Do not invent a five-second-plus-one-millisecond request-gap threshold. A
missing timer registration/event, hidden or paused interval, changed document,
failed native response, no progress for twenty seconds, or missing raw records
refuses continuity. A timer callback skipped by the native busy guard remains
recorded and must be explained by its native state; fabricated aggregate
counters cannot stand in for attempts or completions.

R3 owner refresh performs the existing real passkey ceremony while the native
view keeps running, then activates the native `Check session` control to update
its cookie/CSRF view. It does not pause, reset phases or reset cadence counters.
Controls must retain an inflight refusal and distinguish a native UI pause from
a merely asserted probe-active flag. If the frozen product cannot refresh this
way, preserve that counterexample; do not change a frozen package or weaken the
full-interval contract. Native supervisor/clock controls remain separate.

## Source-bound S1, session and grader closeout joins

S1 records bind both actual outer stop receipt and actual runtime receipt by
file hash. Require zero command/wrapper/child exits, exact admitted command,
unit/cgroup, confirmed stop, no forced shutdown, unchanged inputs, matching
owner-admitted headroom binding and the full registered rate profile. Derive
each phase maximum from the runtime phase timestamps; derive transition from
exposure elapsed minus offered seconds. A supplied maximum that differs from
these raw timestamps refuses admission. Historical native-R2 records need the
same explicit normalized phase/stop binding; descriptive elapsed prose is not
a phase witness. No fabricated receipt can authenticate its own authority.

Frozen `8fb6f413` uses `fresh=false` for ordinary node control publication,
an eight-hour session lifetime and a thirty-minute idle timeout. The R3 bridge
may avoid eager UV renewal only for `GET /v1/console/nodes` and
`PUT /v1/console/nodes/sim[0-9]{4}/config`. All session, CSRF, Origin and status
checks remain. Authenticate actual expiry beyond the remaining offered interval
before launch; keep the real periodic management/UI activity. No general
skip-fresh switch or authentication-policy change is admitted.

Grading emits `pending_grader_stop`, never final acceptance. A later, separate
default-contained closeout binds its immutable result hash and actual grading
launcher receipt, exact command/unit/cgroup, zero exits and confirmed stop. It
also rehashes the original pending receipts and complete stopped manifests.
Only a fresh exclusive final receipt may describe acceptance; the measurement,
runtime and grading results retain their original states and bytes. Missing or
substituted grading stop is a refusal, even when all ten gates were true.

### Cross-job and phase forgery controls

Before correction, add literal controls that mix otherwise valid runtime and
outer receipts from different jobs, change a checkpoint output inode/path,
change source helper/profile, alter the independent launcher activation anchor,
or forge a phase elapsed value. Each must refuse S1. Require the runtime's actual
service/cgroup identity and checkpoint root device/inode to match the source
outer receipt and separately admitted output; a common descriptive binding
label cannot establish this. Reparse the complete source checkpoint manifest,
original simulator summary and complete created-event coverage. Runtime phase
records must have exactly the six registered phases, start setup at the
independently observed systemd activation anchor, preserve disjoint order and
meet every local/global ceiling. The exposure record must enclose the actual
native begin bracket and conservative full end. The same phase validator is
mandatory again before grading, including refusal of forged elapsed fields.

The closeout artifact stays `pending_closeout_stop`. The coordinator's actual
closeout launcher exit/resource/empty-stop receipt is the terminal ledger join;
do not label the artifact final acceptance before that observation, and do not
create another recursive launcher layer to attest the final ledger write.
