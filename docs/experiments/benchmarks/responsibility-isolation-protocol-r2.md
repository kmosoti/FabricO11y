## Questions and fixed contract

H1: resource pressure is partly avoidable demand from copies, whole-file materialization, cached inventory or worker barriers, rather than simply a need for larger caps. H0: these native boundaries show no concentrated avoidable demand under the tested coordinates. Describe evidence per boundary; this screen cannot establish that an unimplemented alternative works.

H1-observer: counted allocation, detailed counters or external sampling materially change useful-work cost. H0-observer: their cost is below the observed fresh-process variation. Primary observer endpoint is median useful-work wall duration; also retain CPU, allocations and memory. A 10% change with consistent direction in at least four of five pairs is a screening signal, not statistical proof. Otherwise report inconclusive or no detected change. An optimization smaller than measured observer perturbation is inconclusive.

H1-scaling: extra native sealer workers reduce inclusive pass time; H0: useful pass completion does not improve. Report speedup alongside total process CPU and live/RSS inventory, never reserve CPUs according to worker count. Exact byte custody and query answers are hard constraints in every case.

## Execution stages and frozen matrix

1. **Preflight**, untimed for interpretation: every distinct case below, plain and counted allocator once, native adapters and independent Python body/query/ACK checks. Use the actual registered record count. `BENCH_PREFLIGHT=1` reduces repeated operations/query repeats, not fixture size. Reject changed/missing/duplicate bodies, altered/missing/duplicate query rows and changed ACK hashes. Check all first/warm answers outside their operation spans. A preflight failure stops measurement launch; preserve its trace and owned cleanup.
2. **Calibration**: observation-mode fixture (900-byte bodies, 4,096 records), five fresh-process repetitions of minimal/500-ms/detailed-100-ms capture, and five matched plain/counted minimal pairs. Detailed adds per-boundary proc IO; sampler also records whole-process/cgroup state. Long hash/format batches make observer opportunity visible. Timer/CPU-clock resolution and empty-boundary overhead are retained. Calibration results must be written before main campaign launch. No recursive disk walk in a timed polling loop.
3. **Main screen**: five fresh-process plain/counted pairs, alternating AB/BA. Groups sequential: collection, delivery, storage, processing, query, control, scheduling, observation. Every trial is stopped, independently checked, recorded, compressed and cleaned before the next. No concurrent build, check, analysis, fixture preparation or other owned benchmark.

Native fixture seed 42; 128 logs per Batch; alternating repeated/printable deterministic entropy; unique tags; exact original encoded Batch bytes. Core shape is 4,096 records, body 900 bytes, timestamps sorted. Collection/delivery/storage/processing/query additionally use 128 and 3,500-byte bodies. Control uses 1/20/200 nodes (size argument is cardinality); scheduler uses 1/2/4 workers (size argument is workers). Processing additionally uses reversed and seeded shuffled timestamps at 900 bytes, plus 16,384 and 65,536 records with 1,024-byte bodies (16/64 MiB raw body inventory). Scheduler additionally uses 65,536 records of 1,024 bytes at 1/2/4 workers, giving enough rotated files to exercise workers. No giant Cartesian matrix. Query repeats are three warm calls after a separate first call per shape/plan/layout; preflight uses one warm call. Collection and other repetition bounds remain in the frozen probe source.

Probe CPU affinity uses all five allowed logical CPUs under the shared four-CPU quota. Native delivery client/server share that affinity; no claim of reserved physical cores. Segment query fixture uses a legal native-created empty active journal and native-built Segment, explicitly a constructed layout. Tail and Segment, scan and walk, empty/selective/common/broad **logs** are covered; metrics/rates/traces, mixed layout, pagination, API consumer concurrency, fault/retry, multi-path collection and throttle remain coverage gaps for later extensions. Do not claim complete responsibility coverage or start the three-tier composite from this screen alone.

## Metrics and interpretation

Monotonic wall spans and Linux process CPU ns bracket the same useful operation; report CPU clock resolution. Minimal counters avoid allocating proc reads within each boundary; detailed IO snapshots are outside wall spans and their perturbation belongs to calibration. Store bounded timing rows and flush after useful work. Record final process VmHWM even if external sampling misses short work. Whole-process setup, validation and teardown duration is separate from operation duration.

Record useful units, source/encoded bytes, source/binary/harness hashes, exact argv/env, source revision/diff, live baseline/peak/incremental/cumulative requested allocations, process CPU/HWM, cgroup CPU throttling and memory categories/events/pressure before/after. Proc IO and overlayfs timings are logical buffered behavior, not physical-device or cold-cache claims. Allocation requested bytes are traffic, not simultaneously resident inventory. Process AS is not an RSS limit; cgroup file cache is not process heap.

For each trial keep count, median, maximum, sum and normalized demand. With fewer than 1,000 comparable samples, p99 is null with an insufficient-population label. Do not pool differing cases, first and warm calls or correlated samples into a production tail. Across five processes report median/range and preserve each trial. No variance extension in this finite screen: coefficient of variation above 20% is labeled unstable, with follow-up proposed rather than rerun until a favorable result. No silent exclusion; ambient shared-host activity, cgroup throttling and memory pressure stay in the record. Failed trials stop the phase.

Calibration is a gate for interpretation, not a timing pass threshold. Empty-boundary overhead above 1% of an operation's median labels that boundary observer-sensitive; report its batch sum and recommend aggregation for confirmation. Do not subtract overhead to manufacture a corrected result. The initial machine quota is a rate ceiling, not a per-thread occupancy guarantee.

## Budgets, custody and cleanup

Child wall <=180 s; aggregate campaign <=3,600 s; each child AS <=2 GiB, combined client/server up to 4 GiB AS, with shared memory headroom checked between trials. A cgroup memory charge near its 16 GiB limit is not attributed to owned processes without categories/deltas. Per-trial logical scratch <=1 GiB, 4 GiB free disk floor, retained compressed evidence <=256 MiB per phase, one owner-marked scratch tree at a time. Predict conservative fixture/output footprint before launch and inventory it after timing; poll timeout/free space, not recursive tree size. These are controlled guardrails, not hard instantaneous product limits.

Resource constraints are recorded as: host quota/physical limit; configurable policy; code-enforced setting range; correctness invariant; current algorithm's demand; or ambient shared-host pressure. Crossing a guardrail stops that trial with diagnostic evidence. It may motivate smaller tasks, streaming/external merge, copy reduction, admission/backpressure or cache eviction. It does not authorize weakening exactness, durability or reclaim order. Changing a registered budget/workload requires a prospective protocol addendum.

Before deleting scratch preserve command/env, fixture recipe and hashes, raw timing rows, final high-water/cgroup context, every query verdict/digest, native replay/ACK custody outcomes, failure diagnostic stderr and relevant replay/query records on failure. Successful answer bodies may be retained only for the first plain repetition; all answers are independently graded before deletion. Retain source Batch records for first plain repetition of each case. No credentials/private keys in evidence. Remove only marker-matched owned directories and record logical bytes/free space/exit. Preserve previous runs and unrelated cache. Final result must list coverage gaps and next experiments; no caps or shipping defaults change from this screen.
