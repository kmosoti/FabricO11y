# Corruption/reopen oracle: preregistered assumptions

This add-on uses only the supplied `Batch`, `Cursor`, and `Journal` public API and observed bytes in directories it creates. It does not read alpha implementation source or rely on a private filename or record layout. The six earlier tests and their SHA256 freeze remain unchanged.

## Property and observation boundary

After two successful appends and clean close, both batches are acknowledged under successful-sync and stable-ancestor assumptions. A copy with one flipped bit in one byte of an append-bearing file may either fail to open explicitly, or open with the original next sequence and exact original committed content. A lower next sequence is an acknowledged-batch loss. An accepted mutation of an identifiable OTLP log body byte without restoring that byte is changed committed content. The supplied API lacks replay, so the latter inference is limited to exact stored wire bytes; a public replay/inspection API would make the content oracle direct.

The test takes snapshots before append, after the first append, and after the second append. It selects a file only if exactly one regular file grows by append-only extension at both steps. It searches each appended range for the exact `prost` encoding of the returned canonical `Batch`. A candidate header length must unambiguously match that encoding's length as a little-endian 32- or 64-bit integer before the encoded batch. Bytes after the encoding and before the next append boundary are end-marker candidates. If any of these regions cannot be identified, the test reports a missing external seam rather than inventing a layout.

The source journal and a separate exact golden copy are kept before mutation. Every case copies only the golden files, records target path, source size, SHA256, byte offset, original byte, and flipped byte in a manifest, and changes exactly one byte with XOR `0x01`. The selected cases cover both append ranges, header-length bytes, two known log-body bytes, and first/last trailing bytes, with no more than 128 cases. A clean golden copy is reopened as a positive control. Cases stop on the first counterexample or missing seam. Successful disposable copies and the redundant original source are removed; the tiny golden source and manifest remain under `data/`. On failure, the first failing copy remains too.

The test enforces a 9 MiB live scratch ceiling and a 110 s internal stop, below the requested 10 MiB/120 s limits. This is a correctness probe; elapsed time is only a stop guard and is not recorded as a performance result. It does not inject a write or sync failure, simulate power loss, infer FOL2 behavior, or test server dedup.

## Reproduction

From `target/alpha-journal-oracle`:

```sh
CARGO_HOME=/home/kmosoti/projects/fabric_o11y/target/alpha-cargo \
CARGO_TARGET_DIR=/home/kmosoti/projects/fabric_o11y/target/alpha-oracle-build \
cargo test --offline --locked --test corruption_reopen -- --nocapture
```

`SHA256SUMS.corruption.v1` preserves the first executed freeze. This evidence-retention revision is frozen in `SHA256SUMS.corruption` before its execution. Compiler diagnostics must be filtered so no alpha implementation source excerpt is displayed.
