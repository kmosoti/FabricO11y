These are external observations, not implementation-source assumptions.

## Retained evidence

The exact unmutated copy and [mutation manifest](data/corruption-182-0/mutations.tsv) are under [data/corruption-182-0](data/corruption-182-0). The append-bearing source was 349 bytes, SHA256 `3f4da49bedb9eace6cf11cf665e8c3a01af2f796025c98f01899dde201445bf5`. The separate identity file was 28 bytes, SHA256 `5885a11855d413d9051cd9a2003c77ea0c01b4b617b89506a7736980b737af60`.

The ten one-byte, one-bit cases targeted offsets `4, 111, 119, 158, 173, 178, 285, 294, 333, 348` in the 349-byte source. These cover both observed header-length fields, two known OTLP body positions in each append, and the first and last trailing bytes of each append. The manifest records the original and flipped byte for every case before the mutation. Each mutation was applied only to a copy; successful disposable copies were removed. The complete standalone scratch package occupied 178,727 bytes after the run, below the 10 MiB ceiling. The command completed below the 120 s limit. No latency or throughput metric was collected.

There is **no counterexample** among these selected positions. An open error counted as explicit rejection. If a mutated copy opened, the oracle required the original `next_sequence`; for body mutations it also required restoration of the original body byte in the stored wire encoding. The supplied public API cannot directly replay or inspect already committed batches, so exact post-reopen semantic content remains a limited inference from raw bytes. This result does not establish behavior for all possible byte offsets or multi-byte damage.

## Remaining fault seam

An integrator-provided frozen format or test I/O seam is still needed to inject a short write, failed data sync, failed marker sync, failed recovery-required-sidecar clear, and an interrupted partial append at known points. Those probes must verify that a known storage error quarantines the writer and that readable bytes do not silently authorize reopening. Physical power loss and server retry/dedup remain outside this journal oracle.
