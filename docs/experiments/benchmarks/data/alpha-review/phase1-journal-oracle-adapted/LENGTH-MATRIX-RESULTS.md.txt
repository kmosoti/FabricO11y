# Length-bit matrix and exact replay result

Status: **failed with a minimized black-box counterexample**. This is independent phase-1 preparation, not phase promotion. The oracle did not read `src/alpha` or edit product/documentation files. The earlier six-test and ten-mutation frozen files were unchanged; their SHA256 checks still pass.

Exit: **101**. Cargo reported `build-finished success=True`, then one test failed. The command completed within the 120-second limit. Compiler output was captured in `length-matrix-cargo-test.jsonl` and `length-matrix-cargo-stderr.txt` and filtered without exposing alpha implementation source excerpts. Post-run `sha256sum -c SHA256SUMS.length-matrix`, `sha256sum -c SHA256SUMS`, and `sha256sum -c SHA256SUMS.corruption` all exited **0**. No performance result was taken.

The test first reopened both the closed original and an unmodified independent copy. On each, `Journal::replay` returned the exact two acknowledged `Batch` values, including OTLP bytes, cursors, identity, generation and sequence. It then ran cases 0–7 successfully and stopped at the first failure, case 8. The frozen source defines all 64 length-bit mutations and eight payload/trailer controls; cases 9–71 were **not run** after the counterexample.

## Smallest selected counterexample

The source journal's append-bearing file was observed as `batches.faj`, size **349 bytes**, SHA256 `98d2d38a4a599254c37df0db293314c7763435976c750395f1b97b4bceca77ec`. A separate exact golden source was retained. The [manifest](data/length-matrix-181-0/mutations.tsv) was synced before each mutation.

Case 8 is `first-length-byte-1-bit-0`: at byte offset **5**, flip `0x00` to `0x01`. The inferred four-byte little-endian length changes from **146** to **402**. There were **337** bytes remaining from the encoded payload start to EOF. The changed length is below both the 1 MiB encoded-batch cap and the configured 2 MiB journal capacity. This is one byte and one bit; no other byte of the pre-open copy differs from the golden source.

`Journal::open` **succeeded** on the mutated copy, but `next_sequence()` was **1**; the clean acknowledged source had **3**. Inspection after that successful open found the copied append-bearing file truncated from **349 bytes to 0**. The exact [pre-open mutant](data/length-matrix-181-0/case-008-preopen/batches.faj) is retained with SHA256 `9d374064c52d4ad67aebdef473b93140c9aeae153e972d50868ef017332920d5`. The [post-open file](data/length-matrix-181-0/case-008/batches.faj) and golden source remain separately inspectable. The case therefore shows acknowledged history quietly lost after a length corruption that should have been rejected or preserved. Replay of the mutated copy was not attempted because the sequence assertion failed first.

The standalone oracle directory occupied **250,134 bytes** after retaining this evidence, below the 10 MiB limit. The test process exited; no long-lived child was started.

## Remaining seam

`Journal::replay` now supports exact committed-content checks after accepted opens. Write/sync fault cases still need an integrator-provided frozen fault seam: short write, data-sync failure, marker-sync failure, recovery-required-sidecar clear failure, and interrupted partial append. This result does not test physical power loss or server retry/dedup.
