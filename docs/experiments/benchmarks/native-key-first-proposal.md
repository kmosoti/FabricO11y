# Native key-first query admission

Prospective supplement to [the native frontier protocol](native-frontier-protocol.md), 2026-10-09. This is a bounded mechanism screen, followed only on admission by fresh confirmation. Production behavior remains unchanged unless compiled with `FABRIC_KEY_FIRST_EXPERIMENT=1`; both arms explicitly set `FABRIC_BORROWED_LOG_EXPERIMENT=0` and clear unrelated experiment flags.

The candidate compares a row's complete canonical key against the strict page boundary and current `limit+1` heap threshold before literal body matching or result cloning. Equal threshold keys remain rejected, preserving stable ties. It changes callback admission, never source reads, typed/JSON validation, raw digests, snapshot coverage, group selection, page tokens or the final selector. H1 is reduced first-page CPU where most decoded rows cannot enter the bounded heap. H0 is no useful reduction, or adverse broad-query cost because decoding dominates or the additional checks cost more than avoided work. This introduces neither an index nor a format change.

## Fixtures and measurement boundaries

Each fresh native child generates 2,048 logical rows from independently decodable producer batches, one node and generation, with four equal observed timestamps per rank. Bodies contain 16 or 1,024 UTF8 bytes; attributes are absent or eight 128-byte values. Six queries cover absent literal, `SEL!` (128 matches), `COM!` (1,024), absent contains predicate (2,048), empty literal (2,048) and Unicode `λ` (2,048). Limit is 64. Markers occur at the body suffix. Tail and sealed layouts each run Scan and Walk.

Four first-page calls per population yield one first call and a median of three subsequent calls. Each population also drains the complete canonical continuation chain outside the timing clock. The unchanged Python query oracle grades all pages against the exact producer ledger; three representative output defects per multipage chain must be rejected, with complete counterexample vectors retained. Timings establish first-page cost only, never complete-chain CPU. First/reuse labels describe History calls, not OS cold/warm cache state.

Screen cells are widths 16/1,024 × attribute counts 0/8, sorted source rank and seed 42. Run counted phases-on, counted phases-off, then plain builds; balance arm order within cells. Four cells × three regimes × two arms produce 24 fresh children, 2,304 measured first pages, 576 complete canonical chains, 11,040 canonical pages and 1,440 rejected output controls. Phase-on/off comparisons assess observer sensitivity; nested inclusive phase intervals must not be summed. Allocation comes from counted builds; CPU benefit comes from plain builds. Whole-child GNU time CPU/RSS and launcher cgroup observations have wider boundaries than query calls.

Fresh confirmation reuses the exact four frozen binaries on width 1,024, eight attributes, seeds 43/44/45 and sorted/shuffled source ranks. Counted phases-off then plain yields another 24 children with the same call/chain/page/control totals. Source shuffling changes admission churn. Native sealing sorts full canonical keys; these 2,048-row fixtures occupy one native 8,192-row group and do not test mixed Parquet locality or new group pruning.

## Admission and guards

Screen primary benefit: plain reused first-page CPU ratio ≤0.90 for tail Scan/common on the wide eight-attribute cell. Its plain wall ratio must be ≤1.05, and counted requested/peak incremental query heap ratios ≤1.05. Source inspection motivates this choice: tail Scan clones decoded result rows before the bounded selector rejects them, so key-first admission can avoid both suffix matching and cloning after the heap fills. Owned sealed readers already construct and validate every selected row; their saved matching work is an explicit diagnostic/null regime, not evidence of avoided Parquet decoding. All other plain first/reuse population CPU and wall ratios must be ≤1.05; every complete oracle answer and native corruption outcome must agree. Ratios are candidate/baseline, using each child boundary separately. A failed guard is a null/adverse result; no population pooling or relaxed threshold is allowed.

Only a root-authored admission receipt containing `decision: "confirm"` and the exact screen `result.json` SHA256 authorizes confirmation. Confirmation requires the same primary benefit and all guards for every held-out seed/order pair; otherwise retain non-nomination. This is exploratory evidence, not integration or deployment qualification. Earlier borrowed-log CR2 CPU rejection remains unchanged.

Before measurement, native controls run with flag 0 and 1: the new `key_rejected_corrupt_attributes_still_make_history_incomplete` fixture first fills the `limit+1` heap, then presents a later canonical key with invalid attributes JSON inside a valid size/schema/digest envelope. Actual Scan and Walk must still mark the answer incomplete. Existing `completion_storage` controls independently grade missing query tables, missing raw batches and raw integrity defects. Existing selector, borrowed-reader validation and snapshot-transition checks remain required broader checks; the new fixture includes absent bodies, while the measured fixture includes positive Unicode and empty/absent predicates. Exact page boundaries and stable timestamp ties are exercised by full drains and the new full-key unit test. These finite fixtures do not enumerate every snapshot, node or corruption combination.

## Reproduction and preservation

All commands run serially under the unchanged resource launcher. Example screen command (root assigns admission time from the shared ledger):

```sh
python3 -B tools/resource_group.py -- python3 -B tools/bench/labs/cross_system/run_native_job.py --id key-first-screen-01 --lab query --reserve-mib 192 --seconds 1100 -- python3 -B tools/bench/labs/cross_system/key_first_run.py --out docs/experiments/benchmarks/data/native-frontier-01/query/key-first-screen-01 --mode screen --build-seconds 550 --run-seconds 500
```

The controls use the same wrapper with `--id key-first-controls-01`, `--mode controls`, and an independently admitted ≤300-second allocation. Confirmation uses `--id key-first-confirm-01`, `--mode confirm --binaries` pointing to the screen directory and `--screen-admission` pointing to the root receipt; inner run ≤450 seconds. Build jobs are limited to two, offline and locked. Root charges all tests, builds, screens, confirmation and reduction to the shared round and initial query target of ≤1,800 cumulative seconds; inability to fit means no confirmation claim.

Freeze sources, Rust inputs, protocol supplements, compiler flags and four binary hashes before measurements. Plain/count builds share the data-drive Cargo target cache, then copy and hash frozen executable bytes; build-cache reuse is reported and is not independent build timing. Every native member, source ledger, page and counterexample is retained losslessly in a bounded deduplicated gzip object pool with complete relative-path maps and two exact readbacks before successful scratch deletion. Category-wide accounting includes earlier query jobs and reserves 192 MiB within the 384 MiB cap. Raw cases stop at 480 MiB, bounded below the 512 MiB failure envelope; scratch ≤8 GiB and free space ≥16 GiB. Preservation failure leaves the complete scratch tree and stops. Root removes frozen binary copies only after confirmation/disposition and authenticated hash readback; source archives, hashes, receipts, maps and semantic evidence remain.

No workload has run on this supplement at preparation time. Measured failures and receipts belong to their actual frozen sources; source inspection alone cannot establish a performance gain.
