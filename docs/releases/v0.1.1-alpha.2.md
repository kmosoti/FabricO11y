# FabricO11y v0.1.1-alpha.2

`v0.1.1-alpha.2` hardens FabricO11y across all local IPC, engine transport, storage custody, MCP/CLI rendering, quota fairness, and release supply-chain trust boundaries while maintaining zero-UI `fabric-client` and `green-infra` compatibility.

## Highlights

- **Mutual HMAC-SHA256 loopback authentication & Slowloris isolation:** `fabric::canonical`, `fabric-client`, `fabric-server`, and `spindle` authenticate over TCP using a 4-frame mutual HMAC-SHA256 challenge-response protocol bound to fresh 256-bit client/server nonces and `request_mac` — raw bearer credentials never cross loopback sockets, and `fabric-server` isolates pre-auth connections in a bounded non-blocking `poll` gate (`250ms` timeout) ahead of `ConnectionWorkerPool`.
- **Authenticated Greptime loopback transport:** `fabric-server` now fails closed when `engine_endpoint` is set unless `engine_auth_token_file` (sending `Authorization: Bearer <token>` on `/v1/sql`) is configured or `allow_unauthenticated_loopback_engine = true` is explicitly set.
- **TOCTOU-free credential & atomic live-state custody:** Credential loaders (`fabric`, `fabric-server`, `fabric-client`) open once with `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC` and validate `fstat` metadata on the opened FD. `fabric-store` replaces pathname re-entry in `write_live_state_atomic` with anchored `OwnedFd` `openat` + `fstat` `(dev, ino)` verification + `renameat` + directory `fsync`.
- **Umask-independent custody permissions & `SO_PEERCRED` checks:** Custody directories (`0o700`), state/Parquet/SQLite/redb/lock files (`0o600`), and Unix domain sockets (`daemon.sock`, `ingest.sock`, `spindle.sock`, `0o600` + `SO_PEERCRED` same-UID verification) enforce strict private modes regardless of ambient `umask`.
- **Fair-share per-origin canonical & projection quotas:** Enrolled origins omitted from `node_quota_bytes` automatically receive a fair-share byte cap across canonical (`Ledger`) and analytical (`Projection`) storage.
- **Untrusted telemetry framing & terminal sanitization:** `fabric-mcp` frames canonical telemetry with `untrusted_telemetry: true` metadata and escapes control/delimiter sequences; `fabric` and `fabric-query` sanitize C0/DEL/ESC/C1/bidi controls in table renderers and error output; `FsChurnTracker` evicts vanished paths each cycle and bounds tracked entries (`4096`).
- **Release pipeline hardening & dynamic version parameterization:** Verified SHA-256 `rustup-init` `1.29.3` installation, fail-closed protected-`main` ancestry gating on tagged releases, and dynamic `vX.Y.Z[-pre]` packaging across RPM, Debian `.deb`, `.tar.zst`, and Nix.

## Release Artifacts & Verification

Each tagged release publishes:

- Fedora RPM (`fabrico11y-0.1.1-0.alpha.2.fc44.x86_64.rpm`)
- Debian 12/13 package (`fabrico11y_0.1.1-alpha.2_amd64.deb`, internal version `0.1.1~alpha.2`, `GLIBC_2.36` floor)
- Portable Linux `x86_64` tarball (`fabrico11y-0.1.1-alpha.2-x86_64-unknown-linux-gnu.tar.zst`)
- `SHA256SUMS` and `RELEASE-EVIDENCE.json`, all attested via `actions/attest-build-provenance`

Verify downloads before installing:

```sh
sha256sum --check SHA256SUMS
gh attestation verify fabrico11y_0.1.1-alpha.2_amd64.deb --repo kmosoti/FabricO11y
gh attestation verify fabrico11y-0.1.1-alpha.2-x86_64-unknown-linux-gnu.tar.zst --repo kmosoti/FabricO11y
gh attestation verify fabrico11y-0.1.1-0.alpha.2.fc44.x86_64.rpm --repo kmosoti/FabricO11y
```
